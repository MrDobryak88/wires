# Kanban-доска в GitHub Projects

> Простая система задач для двух человек. Без Jira, без настроек, бесплатно.

---

## 🤔 Что такое Kanban

Kanban — это визуальная доска с колонками, где карточки (задачи) двигаются слева направо по мере выполнения.
[ To Do ] → [ In Progress ] → [ Done ]

**Принципы:**
- Видно что делается прямо сейчас
- Лимит на WIP (Work In Progress) — не берите больше 2 задач одновременно
- Задача не попадает в Done без критериев готовности

## 🚀 Создание доски (5 минут)

### Шаг 1: Откройте GitHub Projects
1. Зайдите в ваш репозиторий на GitHub
2. Вкладка **Projects** (рядом с Code, Issues, Pull Requests)
3. Нажмите **New project**
4. Выберите шаблон **Board** (не Table, не Roadmap)
5. Название: `Alpha Development`
6. Нажмите **Create project**

### Шаг 2: Настройте колонки
По умолчанию будут 3 колонки. Переименуйте их:

| Колонка | Назначение |
|---------|------------|
| **To Do** | Задачи которые нужно сделать |
| **In Progress** | Задачи в работе (максимум 2 на человека) |
| **Done** | Завершённые задачи |

**Опционально добавьте:**
- **Backlog** — идеи на будущее (вне MVP)
- **Review** — задачи на ревью (PR создан, ждёт проверки)

### Шаг 3: Добавьте поля к карточкам
Нажмите **+ Add field** в правой части доски:

| Поле | Тип | Зачем |
|------|-----|-------|
| **Assignee** | People | Кто делает задачу |
| **Labels** | Labels | Тип задачи (feature, bug, docs) |
| **Estimate** | Number | Оценка в днях (1, 2, 3) |
| **Iteration** | Iteration | Неделя (Week 1, Week 2...) |

## 📝 Создание задачи

### Способ 1: Через интерфейс доски
1. Нажмите **+ Add item** в колонке **To Do**
2. Введите название: `CRUD для уровней подписки`
3. Нажмите **Enter**

### Способ 2: Через Issue (рекомендуется)
1. Вкладка **Issues** → **New issue**
2. Заголовок: `CRUD для уровней подписки`
3. Описание (шаблон ниже)
4. Labels: `feature`, `tier`
5. Assignee: назначьте себя
6. Projects: выберите `Alpha Development`
7. Нажмите **Submit new issue**

**Шаблон описания задачи:**
```markdown
## Что нужно сделать
<!-- Кратко опишите задачу -->

## Критерии готовности
- [ ] Entity Tier создана
- [ ] TierRepository с методами findByCreatorId
- [ ] TierService с CRUD операциями
- [ ] TierController с эндпоинтами GET/POST/PUT/DELETE
- [ ] Эндпоинты видны в Swagger UI
- [ ] Юнит-тесты на TierService
- [ ] `mvn clean verify` проходит

## Оценка
2 дня

## Зависимости
<!-- Какие задачи должны быть сделаны до этой? -->
- #5 (Flyway миграция для таблицы tiers)

## Дополнительная информация
<!-- Ссылки, скриншоты, примеры -->
```

## 📏 Правила доски
#### Лимит WIP (Work In Progress)
Максимум 2 задачи в In Progress на человека.
* Почему? Junior-разработчик не может эффективно работать над 5 задачами одновременно. Лучше закончить одну, чем начать пять.
* Если лимит достигнут — закончите текущую задачу, прежде чем брать новую.

#### Определение Done
* Задача попадает в Done только если:
* Код в main (PR merged)
* CI зелёный
* Критерии готовности из описания выполнены
* Второй разработчик подтвердил (ревью пройдено)

#### Не Done: «я почти закончил», «осталось написать тесты», «работает локально».

#### Приоритеты
##### Используйте labels для приоритета:
* 🔴 priority:high — блокирует других, делать срочно
* 🟡 priority:medium — обычная задача
* 🟢 priority:low — можно отложить

#### 🔄 Работа с доской
Ежедневный ритуал (5 минут утром)
Откройте доску
Посмотрите колонку In Progress — что вы делаете сегодня?
Если задача готова → переместите в Done
Возьмите новую из To Do → переместите в In Progress
Назначьте себя (Assignee)
